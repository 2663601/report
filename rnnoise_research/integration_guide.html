3. WebRTC Binary Spectrum 集成经验

原理

直接调用项目已有的 VQE/AEC_webrtc/delay_estimator.c 和 delay_estimator_wrapper.c。封装层只需做 FFT 将时域信号转为频谱。

关键步骤

  1. 累积输入到 PART_LEN=64 样本的块
  2. 加 sqrtHanning 窗 → 128 点实数 FFT（aec_rdft_forward_128）
  3. 提取 65 个频带的幅度谱
  4. 调用 Evz_AddFarSpectrumFloat() 和 Evz_DelayEstimatorProcessFloat()

踩坑记录

Segfault：必须在使用 FFT 前调用 aec_rdft_init()，否则内部函数指针为 NULL。
内存分配：原始代码使用预分配 char buffer 的方式（非 malloc），需要分配足够大的连续内存（64KB）并按偏移传入。
延时单位：返回值是"块数"（每块 = PART_LEN = 64 样本），需要乘以 PART_LEN 转换为采样点。

4. AEC3 Matched Filter 集成经验（ewan-xu/AEC3）

算法架构

EchoPathDelayEstimator::EstimateDelay()
  ├── AlignmentMixer::ProduceOutput()     → 多通道混合为单通道
  ├── Decimator::Decimate()               → 4倍降采样（16kHz→4kHz）
  ├── MatchedFilter::Update()             → 多段 NLMS 自适应滤波
  │     └── MatchedFilterCore()           → 逐样本 NLMS 更新
  ├── MatchedFilterLagAggregator::Aggregate() → 直方图投票聚合
  └── ClockdriftDetector::Update()        → 时钟漂移检测

核心 NLMS 算法

for each sample i in sub_block:
    s = Σ(h[k] * x[x_start_index + k])    // 滤波器输出
    e = y[i] - s                            // 误差
    x2_sum = Σ(x[k]²)                      // 信号能量
    if (x2_sum > threshold && !saturation):
        alpha = smoothing * e / x2_sum
        h[k] += alpha * x[k]               // NLMS 更新
    x_start_index--                         // 滑动

关键参数

参数值说明
kBlockSize64输入块大小（4ms@16kHz）
down_sampling_factor4降采样倍数
sub_block_size16降采样后每块样本数
num_filters5匹配滤波器数量
window_size_sub_blocks32每个滤波器的窗长
smoothing0.7NLMS 步长
histogram threshold (initial)5初始报告阈值
histogram threshold (converged)20收敛后报告阈值

环形缓冲管理（最关键的坑）

DownsampledRenderBuffer 写入逻辑：
  • write 指针向前递减（每块减 sub_block_size）
  • 数据逆序写入：std::copy(ds.rbegin(), ds.rend(), buffer.begin() + write)
  • read 指针 = write + sub_block_size（最新数据位置）
  • 必须用环形索引处理边界：(wr + i) % buf_size

编译依赖解决

问题解决方案

评估策略：Hold Last Value

公平对比：AEC3 是保守策略（只在高置信度时报告），直接统计"有效帧/总帧"会不公平。解决方案：一旦收敛出延时，后续帧保持报告上一次的值（hold-last-value），这与实际 AEC 系统的使用方式一致。

5. GCC-PHAT 集成经验

算法原理

1. FFT(farend) → X(f), FFT(nearend) → Y(f)
2. 互功率谱: Gxy = X * conj(Y)
3. PHAT 加权: Gxy / |Gxy|
4. IFFT → 互相关函数 R(τ)
5. 找峰值: delay = argmax R(τ)

当前问题

准确率极低（4.4%）：当前实现是滑动窗口方式，但参数和缓冲管理有问题。建议参考成熟的流式 GCC-PHAT 实现（如 xiongyihui/tdoa）重写。

6. 测试数据生成

数据来源

  • delay_metrics_data/：设备采集的延时对齐 lpb+mic 配对（干净回声路径）
  • class_16k/：ESC-50 噪声库（50 类环境噪声，16kHz）
  • near_data/：近端语音（用于双讲场景）

生成的 36 个场景

类型数量参数
纯回声183对设备 × 6种延时(50/100/150/200/300/500ms)
回声+噪声62对 × 3种SNR(20/10/0dB)
双讲62对 × 3种SER(10/0/-10dB)
延时突变62对 × 3种突变(100→200/200→50/300→100ms)

延时突变数据生成的关键

错误做法：把 mic 信号切成两段分别加不同延时再拼接 → 切换点产生脉冲断裂。
正确做法：从同一段连续 mic 信号的不同偏移位置读取： 
n < change_point:  nearend[n] = mic[n + delay1_samples]
n >= change_point: nearend[n] = mic[n + delay2_samples]
这样 nearend 信号本身是连续的，只是回声对应的远端位置发生了跳变。

7. 编译环境与工具链

推荐环境

环境说明

gcc 11.4 + cmake 3.22C++14 标准

编译命令

# 首次编译
wsl -d Ubuntu-22.04 bash -c "rm -rf ~/delay_bench_build && mkdir ~/delay_bench_build && \
  cd ~/delay_bench_build && \
  cmake /mnt/e/server_code/ezvqe_forrtc_250514/ezvqe_forrtc/delay_est_benchmark -DCMAKE_BUILD_TYPE=Debug && \
  make -j4"

# 增量编译（修改代码后）
wsl -d Ubuntu-22.04 bash -c "cd ~/delay_bench_build && make -j4"

# 运行单场景
wsl -d Ubuntu-22.04 bash -c "cd ~/delay_bench_build && ./delay_est_benchmark \
  /mnt/e/.../test_dataset/echo_only_pair0_delay100ms/farend.pcm \
  /mnt/e/.../test_dataset/echo_only_pair0_delay100ms/nearend.pcm 100 16000 160"

关键踩坑

不能在 /mnt/e/ (NTFS) 上编译：CMake 无法在 NTFS 文件系统上复制可执行文件（"Cannot copy output executable"）。必须在 WSL 本地文件系统（~/）中编译，源码通过 /mnt/e/ 路径引用。
WSL2 apt 安装问题：Ubuntu 26.04 太新（镜像源未同步），需要用 22.04 LTS。公司网络可能有代理导致 Hash Sum mismatch。
