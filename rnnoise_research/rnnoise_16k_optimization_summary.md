# RNNoise 16kHz 三版本演进对比与优化总结

## 版本定义

| 版本 | 代码位置 | 年份 | 说明 |
|------|---------|------|------|
| **V1 旧版** | `rnnoise/rnn_data_aoplay.c` + `src/denoise.c` | 2017-2020 | Mozilla 原版 rnnoise 的 16kHz 定制缩小版 |
| **V2 xiph 新版** | `xiph_rnnoise/src/` | 2024 | Jean-Marc Valin 重构的 48kHz 新架构 |
| **V3 我们的版本** | `training/rnnoise_16k/` | 2024 | 基于 V2 架构适配 16kHz 的 tiny 模型 |

## 一、特征提取演进

| 方面 | V1 旧版 (src/denoise.c) | V2 xiph 新版 (48kHz) | V3 我们的 (16kHz) | 变更原因 |
|------|------|------|------|------|
| 采样率 | 16kHz | 48kHz | 16kHz | V2→V3: 适配嵌入式 16kHz 场景 |
| 帧长 | 160 (10ms) | 480 (10ms) | 160 (10ms) | V2→V3: 对应采样率调整 |
| 频带数 | 17 (线性 eband5ms) | 32 (ERB eband20ms) | 22 (ERB eband_16k) | V1→V2: ERB 匹配人耳感知。V2→V3: 16kHz 只有 0-8kHz，22 bands 足够 |
| 频带表 | `eband5ms[]` 线性 200Hz 间隔 | `eband20ms[]` ERB 尺度 0-20kHz | `eband_16k[]` ERB 尺度 0-8kHz | V1→V2: 线性高频太粗，ERB 低频密高频疏。V2→V3: 截取到 Nyquist=8kHz |
| 特征维度 | 37 | 65 | 45 | V1→V2: 去 delta 加全维 pitch。V2→V3: bands 少所以维度缩小 |
| BFCC | 17 维 + delta(6) + delta2(6) | 32 维 (纯当帧) | 22 维 (纯当帧) | V1→V2: **去掉 delta**，GRU 自行学时序变化 |
| Pitch correlation | DCT 前 6 维 | 全 32 维 DCT | 全 22 维 DCT | V1→V2: **保留全维**，让网络精确知道每个频带的谐波性 |
| Spectral variability | 1 维 (8帧历史) | **无** | **无** | V1→V2: 去掉。GRU 隐状态本身建模时序稳定性 |
| 跨帧状态 | cepstral_mem[8][17] | **无** | **无** | V1→V2: 去掉。纯当帧特征，推理更简单、启动更快 |
| Band energy 计算 | 无三角平滑 (或简单平滑) | 三角窗平滑 (overlap bands) | 三角窗平滑 | V1→V2: 三角平滑让频带过渡更平滑，减少增益阶跃 |
| DCT 归一化 | sqrt(2/22) 写死 | sqrt(2/22) | sqrt(2/22) | 不变 |

### 变更原因详解

**V1→V2 去掉 delta/delta2：**
- GRU 天然是序列模型，每帧隐状态编码了全部历史信息
- 手工计算 delta 再喂给 GRU = 重复提供同一信息
- 去掉后减少 12 维特征，减少计算量和存储

**V1→V2 pitch correlation 从 6 维扩展到全维：**
- 旧版只取 DCT 前 6 维 = 只有 pitch 相关性的"整体概要"
- 无法区分"哪个频带是谐波、哪个不是"
- 全维保留让 gain mask 在高频段更精准（不误伤语音高次谐波）

**V2→V3 频带数 32→22：**
- V2 覆盖 0-20kHz 需要 32 bands，16kHz 采样只有 0-8kHz
- 22 bands 在 0-8kHz 范围已经很密（语音核心区 300-3500Hz 有 ~10 个独立 band）
- 更少 bands = 更小模型输出层

## 二、模型结构演进

| 方面 | V1 旧版 aoplay | V2 xiph 新版 (默认) | V3 我们的 tiny | 变更原因 |
|------|------|------|------|------|
| 前端 | Dense(38→16, tanh) | Conv1d(65→128, k=3) + Conv1d(128→384, k=3) | Conv1d(45→16, k=3) | V1→V2: Conv1d 看 3 帧邻居做局部时域聚合。V2→V3: 只用 1 层 Conv1d（tiny 够用） |
| GRU 结构 | 串行级联 + 手工 state 拼接 | 串行级联 + skip connection | 串行级联 + skip connection | V1→V2: skip connection 替代手工 state 拼接 |
| GRU 输入 | 70 维 (state + raw_input 拼接) | 384 维 (前一层输出) | 16 维 (前一层输出) | V1→V2: 不再重复注入 raw_input。V2→V3: 缩小到 16 对齐 NEON |
| GRU 隐藏 | 不一致 (16/16/32) | 统一 384 | 统一 16 | V1→V2: 统一尺寸简化设计。V2→V3: 16=NEON 最小对齐单元 |
| GRU 层数 | 3 (vad+noise+denoise) | 3 (gru1+gru2+gru3) | 3 | 不变 |
| 输出方式 | 只用最后层 state(32) | **cat(conv+gru1+gru2+gru3)** → Dense | cat(conv+gru1+gru2+gru3) → Dense | V1→V2: skip connection 让所有层信息直达输出 |
| 输出维度 | 18 bands | 32 bands | 22 bands | 对应频带数 |
| 参数量 | ~16.9K | ~3.5M | ~8.5K | V2→V3: 嵌入式约束，极度缩小 |
| NEON 对齐 | ✗ (70 维) | ✗ (384 维可整除但太大) | ✓ (全 16 倍数) | V2→V3: 嵌入式 NEON 优化需求 |

### 变更原因详解

**V1→V2 Conv1d 前端替代 Dense：**
- Dense(38→16) 只看当前帧单点特征
- Conv1d(k=3) 同时看 t-1, t, t+1 三帧，做局部时域聚合
- 等价于旧版"每层都拼接 raw_input"的信息补充，但更高效（只做一次，不重复）

**V1→V2 Skip connection 替代 state 拼接：**
- 旧版手工设计信息流: VAD→Noise→Denoise，必须按顺序执行
- 新版所有 GRU 输出直接 concat 到 Dense 输出层
- Dense 自己学习从哪层取什么信息（更灵活、不受人为设计限制）

**V1→V2 不再重复注入 raw_input：**
- 旧版每层 GRU 输入都拼接 38 维 raw_input → 70 维大矩阵乘
- 新版 Conv1d 已经把特征压缩好了，后续只传 16 维压缩表示
- 减少了 3× (70-16)×48 = 7776 次多余 MAC/帧

**V2→V3 极度缩小 (384→16)：**
- 嵌入式目标 <120us/帧 ARM
- V2 的 3.5M 参数在 ARM 上需要 >10ms/帧，不可接受
- 16 维 GRU 让 GRU MAC 从 ~1.5M 降到 4608
- 新特征 (45 维含全 pitch corr) 信息量大，小模型也能学好

## 三、训练数据生成演进

| 方面 | V1 旧版 (src/denoise.c main) | V2 xiph (dump_features.c) | V3 我们的 (dump_features_16k.c) | 变更原因 |
|------|------|------|------|------|
| 数据单位 | 逐帧处理 | 整段 sequence (2000帧) | 整段 sequence (2000帧) | V1→V2: 整段处理可以做 Viterbi VAD、RMS 归一化 |
| SNR 控制 | 基于文件能量比 | weighted_rms (A 加权) 归一化 | weighted_rms | V1→V2: A 加权更符合人耳感知，SNR 控制更准 |
| VAD 生成 | 能量阈值 (vad_cnt) | **Viterbi 前向+回溯** | Viterbi | V1→V2: Viterbi 全局最优路径，避免逐帧判断的抖动 |
| 频响随机化 | rand_resp (±0.75 均匀) | **rand_filt (极点/零点对)** | rand_filt | V1→V2: 极点对产生更真实的频响变化（模拟不同麦克风） |
| RIR 混响 | 无 | **支持** (overlap-save 卷积) | 支持 (开关控制) | V1→V2: 让模型学会处理混响环境。V3: 开关可控 |
| 前景噪声 | 无 | **有** (第三路) | 有 | V1→V2: 模拟突发瞬态噪声（键盘、关门等） |
| 削波增强 | 无 | **25% 概率** | 25% | V1→V2: 模拟 ADC 过载，增强鲁棒性 |
| 量化增强 | 无 | **50% 概率** | 50% | V1→V2: 模拟 16-bit 量化噪底 |
| 随机位置采样 | 顺序遍历文件列表 | **随机 fseek** 到大文件中 | 随机 fseek | V1→V2: 更高数据多样性 |
| gain 标记 | g=0 (忽略) | **g=-1** (忽略) | g=-1 | V1→V2: 0 和 "应输出静默" 容易混淆，-1 更明确 |
| 输出格式 | features+gain+vad (float32) | features+gain+vad (float32) | features+gain+vad (float32) | 相同 |

### V3 特有的适配

- **RIR 文件格式问题**：服务器 RIR 是 wav 格式，需 `convert_rir_wav_to_f32.py` 预处理
- **USE_RIR 开关**：可在 `run_server.sh` 中控制是否使用 RIR（排查 NaN 时关闭）
- **lowpass 适配**：`FREQ_SIZE * 3000/8000 * pow(50, rand)`（V2 是 `3000/24000`）
- **多进程数据准备**：`prepare_data_from_list.py` 16 进程并行读 wav

## 四、训练策略演进

| 方面 | V1 旧版 (TensorFlow) | V2 xiph (PyTorch) | V3 我们的 (PyTorch) | 变更原因 |
|------|------|------|------|------|
| 框架 | TF 1.x / Keras | PyTorch | PyTorch | V1→V2: PyTorch 更灵活，状态管理更方便 |
| 优化器 | Adam (lr=5e-4) | **AdamW** (lr=1e-3, β=[0.8,0.98]) | AdamW (lr=2e-3, β=[0.8,0.98]) | V1→V2: AdamW 权重衰减更好正则化。V3: lr 稍高因模型小 |
| LR 调度 | ReduceLROnPlateau | **LambdaLR: 1/(1+5e-5×step)** | 相同 | V1→V2: 持续衰减比阶梯下降更平滑 |
| Batch size | 128 (Keras generator) | 128 | 256 | V3: L40 GPU 显存大，batch 越大收敛越稳 |
| Sequence | 2000 帧 | 2000 帧 | 2000 帧 | 不变 |
| 状态传递 | Keras stateful (隐式) | **states.detach()** 跨 batch | 相同 | V2: 显式 detach 防止梯度回传太远 |
| 权重约束 | WeightClip(±0.499) | **无** (靠 AdamW decay) | 无 | V1→V2: AdamW 的 weight decay 自然限制权重大小 |
| Early stopping | Keras callback | 无 (存 best loss) | 存 best loss | V2: 简化流程 |
| Sparsification | 无 | **可选** (GRUSparsifier) | 无 | V2: 大模型用稀疏化加速。V3: tiny 模型不需要 |

## 五、损失函数演进

| 方面 | V1 旧版 | V2 xiph 新版 | V3 我们的 | 变更原因 |
|------|------|------|------|------|
| Gain target | 直接 sqrt(Ey/Ex) | **clamp(0) + tanh(8g)²** 压缩 | 相同 | V1→V2: tanh² 压缩让接近 1.0 的 gain 更容易学，避免 sigmoid 饱和区梯度消失 |
| Gain loss | `mycost`: 10×L4 + L2 + 0.01×BCE | **感知 loss**: `(pred^γ - target^γ)²` γ=0.25 | 相同 | V1→V2: γ=0.25 次方让小信号误差权重增大（人耳对安静段更敏感） |
| VAD weighting | `2*|y-0.5|` 加权 | `|2v-1|` 加权 + `(1+5v)` gain | 相同 | V2: gain loss 中额外乘 (1+5×vad)，语音段权重 6× |
| Mask | `min(y+1, 1)` | `clamp(g+1, max=1)` | 相同 | 逻辑相同，只是写法不同 |
| Loss 组合 | 10×gain + 1×vad | **gain + 0.001×vad** | 相同 | V1→V2: 大幅降低 VAD 权重，让 gain 学习为主 |
| 数值稳定 | 无特殊处理 | **log(.01+p)** 和 **log(1.01-p)** | 相同 | V2: 加 0.01 偏移防止 log(0) |

### 变更原因详解

**V1→V2 感知指数 loss γ=0.25：**
- 旧版用 L4+L2 混合，对大误差惩罚大
- 新版 `(pred^0.25 - target^0.25)²` 等价于在"感知域"做 MSE
- 0.25 次方压缩让接近 0 的 gain（安静段/噪声段）的误差被放大
- 符合人耳感知：安静时即使很小的噪声也听得到

**V1→V2 target 预处理 tanh(8g)²：**
- 直接 sigmoid(dense) 预测 g∈[0,1]，但 g=1（不压缩）很难精确学到
- `target = g * tanh(8g)²`：g 接近 1 时 tanh²≈1 不变，g 接近 0 时被进一步压低
- 效果：让模型更积极压制噪声（小 gain 的 target 变得更小）

## 六、推理引擎演进

| 方面 | V1 旧版 (rnn_ns.c) | V2 xiph (nnet.c + rnn.c) | V3 我们的 (rnn_16k.c) | 变更原因 |
|------|------|------|------|------|
| 推理框架 | 手写 compute_dense/gru | **通用 nnet 框架** (LinearLayer) | 复用 xiph nnet.c | V1→V2: 通用框架支持任意拓扑。V3: 直接复用 |
| 权重格式 | int8 (scale=1/128) | **int8 + float bias + float scale (1/256)** | int8 + float bias + float scale | V1→V2: float bias 精度更高。per-output scale 支持混合量化 |
| GRU 实现 | 单函数 stride 格式 | **分离 input/recurrent LinearLayer** | 复用 compute_generic_gru | V1→V2: 分离后可独立优化/稀疏化 |
| Conv1d | 无 | **compute_generic_conv1d (线性 mem)** | 复用 | V1→V2: 新架构核心组件 |

| 延迟补偿 | 无 | **delayed_X/P** (1帧延迟) | 无 | V2: 对增益加 1 帧延迟让判断更准。V3: 暂未加（可后续优化） |

### 7.4 Profiling 结论

1. **NN 推理加速 8.3x 完全兑现**：参数量从 16.9K → 8.5K，MAC 从 15456 → 4608，实际推理 9.5µs → 1.2µs
2. **特征提取是绝对瓶颈**：V3 中占 72.3% 总耗时（12.25µs），主要来自 pitch autocorrelation 和 FFT
3. **总加速被固定开销稀释**：NN 只占总耗时的小部分，因此参数砍 50% 只带来总计 1.7x 加速
4. **进一步优化方向在特征提取**：如果能优化 pitch 搜索（如缩小搜索范围或用简化算法），还能再省 5-8µs

## 八、关键问题讨论记录

### 8.1 为什么选方案 A（适配 xiph 新版 dump_features）而不是方案 B/C

- 方案 B (保持旧特征)：37 维特征信息量受限于 17 bands + 6 维 pitch 概要
- 方案 C (混合)：需要同时维护两套特征提取代码
- **方案 A (完全用新版)**：训练数据增强更强（Viterbi VAD、RIR、三路混合），特征信息量更大，推理不需要 cepstral_mem

### 8.2 Pitch correlation 的物理意义

- 语音是准周期信号，pitch period = 声带振动周期
- Pitch 延迟帧 = 当前信号平移一个 pitch 周期后的版本
- Exp[i] = 第 i 频带上"当前帧 vs pitch 延迟帧"的归一化互相关
- Exp≈1: 该频带高度周期性 → 语音谐波
- Exp≈0: 非周期 → 噪声

### 8.3 旧版为什么需要拼接 state

- noise_gru 需要知道"现在有没有语音"→ 拼接 vad_state
- denoise_gru 需要知道"噪底是什么"→ 拼接 noise_state
- 每层都拼接 raw_input 因为 GRU state 只有历史摘要，没有当前帧瞬时特征
- 问题：70 维输入 >> 16 维隐藏层，计算浪费

### 8.4 数据量与模型容量的关系

- 8.5K 参数模型"笔记本容量"有限
- 10000 seq 已足够写满（数据/参数比 2350:1）
- 50000+ seq 边际收益递减
- 如果效果不够应增大模型而非增大数据

### 8.5 RIR 导致训练 NaN 的根因

- RIR 文件是 wav 格式（int16 + 44B header）
- `load_rir()` 用 `fread(float)` 直接读 → wav header 被误读为极大 float32
- 卷积后信号爆炸 → log10 产生 NaN → loss = NaN
- 解决：`convert_rir_wav_to_f32.py` 预处理 + `USE_RIR` 开关

### 8.6 权重导出格式选择

- xiph 支持两种：二进制 blob（运行时加载）和静态 .c 数组（编译时链接）
- 嵌入式场景无文件系统 → 静态 .c 数组更合适
- `dump_rnnoise_weights_xiph.py` 生成兼容 xiph LinearLayer 的静态数组
- WEIGHTS_SCALE = 1/256（xiph 标准，不是旧版的 1/128）

### 8.7 NEON 对齐为什么选 16 而不是 24/32

- float32 NEON: `vld1q_f32` 一次 4 个 → 维度需为 4 倍数
- int8 NEON: `vld1q_s8` 一次 16 个 → 维度需为 16 倍数
- 24 ÷ 16 = 1.5（需要标量尾循环）
- 16 和 32 都满足，16 更小更快
- GRU gate 向量 3×16=48，48÷16=3 整除 ✓

## 十一、客观质量评估 (DNS Challenge 2020)

### 11.1 评估条件

- 测试集: DNS Challenge 2020 synthetic no_reverb (10 条随机抽样)
- 采样率: 16kHz mono
- 特征提取: C 共享库 (libdenoise16k.so, 与 C 推理完全一致)
- 模型推理: PyTorch (加载 .pth checkpoint)
- xiph 48k: 通过 ffmpeg resample 16k→48k→处理→48k→16k
- 指标: PESQ (感知质量), STOI (可懂度), SI-SNR (信噪比)

### 11.2 评估结果

| Model | 参数量 | PESQ ↑ | STOI ↑ | SI-SNR (dB) | 说明 |
|-------|--------|--------|--------|-------------|------|
| noisy (不处理) | — | 1.664 | 0.882 | 7.51 | baseline |
| **aoplay (V1)** | 16.9K | 1.703 | 0.875 | 7.17 | 旧版, 几乎不降噪 |
| **V3 (gru16)** | 8.5K | **1.890** | 0.732 | -24.01 | 我们的 tiny |
| **V4 (gru32)** | 25.7K | 1.849 | 0.734 | -24.04 | 我们的增强版 (训练不充分) |
| **xiph 48k** | 3.5M | **2.012** | 0.789 | -22.03 | 开源标杆 (resample) |

### 11.3 分析

1. **PESQ (感知质量)**:
   - xiph 48k 最高 (2.012) — 3.5M 参数的能力上界
   - V3 (1.890) 比 noisy (1.664) 提升 +0.23, 比 aoplay (1.703) 提升 +0.19
   - V4 (1.849) 略低于 V3 — 因为 V4 刚训练 50 epoch 未充分收敛

2. **STOI (可懂度)**:
   - aoplay 和 noisy 接近 (0.875/0.882) — aoplay 几乎不改变信号
   - V3/V4 STOI 下降到 0.73 — 降噪时有语音失真 (过度抑制)
   - xiph STOI 0.789 — 大模型更好地平衡了降噪与语音保真

3. **SI-SNR**:
   - V3/V4/xiph 都是负值 — 说明输出整体能量被大幅压低
   - 这是频域 gain mask 方法的特性: gain < 1 会降低所有频段能量
   - SI-SNR 对此类算法不是最佳指标, PESQ 更能反映实际感知质量

4. **aoplay 为什么 PESQ 这么低 (1.703)**:
   - aoplay 在 DNS 数据上几乎不起作用 (保持直通)
   - 它是为特定场景 (对讲啸叫) 优化的, 不是通用降噪

### 11.4 待改进

- V4 需要更多训练 (当前仅 50 epoch, 应跑 200 epoch)
- V3 的语音失真问题 (STOI 0.73) 可通过调整 gain smoothing 参数改善
- 增加评估样本数 (当前仅 10 条, 应跑全部 150 条以获得统计显著性)
- 增加按 SNR 水平分组的分析

### 13.5 V4 比 V3 效果差的原因分析

#### 问题现象

V4 参数 3× 于 V3，训练 loss 更低 (0.121 vs ~0.14)，但 PESQ 反而低 0.05 (1.834 vs 1.885)。

#### 根因分析

| 原因 | 详细说明 | 严重度 |
|------|---------|--------|
| **稀疏化未生效** | 训练日志 200 epoch 全程 sparsity=0%。GRUSparsifier 的 step counter 在加载 checkpoint 后未恢复，导致永远达不到 start 阈值 | ⭐⭐⭐ |
| **conv_trim 对齐** | V4 丢弃 4 帧 (40ms)，开头帧使用默认 gain 直通，噪声未处理拉低 PESQ | ⭐⭐ |
| **过拟合训练集** | 25.7K params 在 40000 seq 上可能记忆过多训练分布特征，DNS 测试集分布不同时泛化差 | ⭐⭐ |
| **GRU(32) 未收敛** | 更大模型需要更长训练。V3 GRU(16) 在 200 epoch 已饱和，V4 GRU(32) 可能需要 400+ epoch | ⭐ |

#### 稀疏化未生效的技术细节

```
训练配置: SPARSIFY_START=6000 steps
数据情况: 40000 seq / batch 256 = 156 batches/epoch
200 epochs = 31,200 total steps

理论上 epoch 38 左右 (step ~6000) 应开始稀疏化
但训练日志显示 sparsity_pct 始终为 0.0

原因: 从 INITIAL_CHECKPOINT 加载模型时，sparsifier 的内部
step_counter 被重新初始化为 0，且 model.sparsify() 调用的是
sparsifier.step()，但如果 sparsifier 实例是新建的，它的计数
从 0 开始——如果训练本身也是从 step 0 开始计数，应该在
epoch 38 开始生效。

实际问题可能是: sparsifier 的 step() 在 GPU 上对 p.data.abs() < 1e-10
的判断有问题（之前已修复过一次），或者 sparsifier 实例化时
传入的 GRU module 引用在 .to(device) 后失效了。
```

## 14. 各版本计算量对比 与 GTCRN 参考 (2026-07-30)

### 14.1 背景

对比自研各版本 RNNoise-16k 与开源 GTCRN 的参数量与计算量，明确"小模型高性能"目标下我们所处的算力档位。GTCRN 数据取自其 ICASSP 2024 论文（内容经改写以符合许可要求）：**23.7K 参数、39.6 MMACs/s**，在 VCTK-DEMAND 上 PESQ=2.87。来源：[GTCRN slides](https://sigport.org/sites/all/modules/pubdlcnt/pubdlcnt.php?fid=9363)。

### 14.2 计算口径

- 采样率 16kHz，帧移 160 samples → **每秒 100 帧**。
- GRU 每帧 MAC ≈ `3 × (in×h + h×h)`（3 个门：reset/update/new）。
- 卷积、Dense 按矩阵乘主项计。
- **未计入**：tanh/sigmoid 激活、FFT、band 插值、pitch filter 等特征提取开销（这部分在 16k pipeline 里约 12µs/帧，与网络本身独立）。
- 所以下表 MMAC/s 为**网络主体的理论估算**，与 GTCRN 论文实测值口径略有差异。

### 14.3 对比表

| 模型 | 参数量 | 每帧 MAC | 计算量 (MMAC/s) | 相对 GTCRN | 备注 |
|------|--------|----------|-----------------|-----------|------|
| **V3** (Conv1→16, GRU16×3) | ~8.5K | ~8.2K | **~0.82** | ~2% | 部署主力，极低算力 |
| **V4** (Conv1→16,Conv2→32, GRU32×3) 稠密 | ~25.7K | ~31K | **~3.1** | ~8% | 稠密未稀疏 |
| **V4** 稀疏后 (~65%) | 有效~13K | ~11K | **~1.1** | ~3% | 稀疏推理下 |
| **V4-DF** (V4 + Deep Filtering 头) | ~31.9K | ~32K | **~3.2** | ~8% | DF 头额外开销很小 |
| **V5** (Conv1→128,Conv2→384, GRU384×3) | ~2.86M | ~2.85M | **~285** | ~720% | 仅验证数据/策略，不部署 |
| **GTCRN** (参考) | 23.7K | — | **39.6** | 100% | 论文实测，PESQ 2.87 |

### 14.4 关键结论

1. **算力档位差一个数量级**：V3/V4 仅 0.8~3.1 MMAC/s，是 GTCRN 的 2~8%。这是我们能跑在极低算力芯片上的根本原因，GTCRN 相对"重"。

2. **参数量接近，计算量却差 10 倍**（V4 25.7K vs GTCRN 23.7K，但 3.1 vs 39.6 MMAC/s）。原因：
   - GTCRN 是 **STFT + 2D 卷积 + DPRNN** 结构，在 ~257 个频点的时频图上做密集卷积/时频建模，参数被高度复用在大特征图上 → 每帧 MAC 高。
   - 我们的 RNNoise 是 **22 band + 帧级 GRU**，只在 22 个压缩 band 上算 → MAC 极低。
   - 即"参数少 ≠ 算力低"，两种架构的参数-算力关系完全不同。

3. **V5 (285 MMAC/s) 是 GTCRN 的 ~7 倍算力**，纯属验证用途，证明数据与训练策略无问题（V5 PESQ 已逼近 xiph 48k）。不可部署。

4. **性能-算力权衡**：GTCRN 用 ~13 倍于 V4 的算力换来更高 PESQ（2.87 vs 我们当前 ~1.8-2.0）。我们的目标是在 V3/V4 的极低算力档位内，通过数据/loss/蒸馏等手段逼近 GTCRN 的质量，而非追平其算力。

### 14.5 精度说明与后续

上表 MMAC/s 为理论估算（矩阵乘主项，未含激活/FFT/特征提取）。项目内 `inference/profile_16k.c` 与 `timing_test_16k.c` 可实测真实每帧耗时；如需精确算力对比，建议实测后用实测值替换本表估算值。GTCRN 的 39.6 为论文实测，口径包含其完整前向。

## 15. 波形域 Loss 实验：PESQ 可微分 loss vs MR-STFT loss (2026-07-30)

### 15.1 实验目的

验证"论文里用 PESQ 相关 loss 训练"这一思路在我们的实数 band-gain 小模型上是否有效，并对比标准 Multi-Resolution STFT loss（Yamamoto 2020 开源公式）。两者都从同一个 V3 baseline 小 lr 微调，用 `-df 22` 全频谱特征重建波形后施加波形域损失。

### 15.2 评估结果（50 条 DNS2020, seed=42, C 特征）

| 模型 | PESQ | STOI | SI-SNR | 相对 baseline |
|------|------|------|--------|--------------|
| noisy（基线） | 1.570 | 0.9124 | 9.21 | — |
| V3 baseline（修复特征） | ~1.77 | — | — | — |
| **V3 + MR-STFT loss** | **1.73** | — | — | **-0.04（变差）** |
| **V3 + PESQ loss（torch-pesq）** | **1.909** | 0.7450 | 8.73 | **+0.14（提升）** |
| V5（大模型验证上限） | 2.041 | — | — | 参考 |
| xiph 48k | 2.070 | — | — | 参考 |

### 15.3 关键结论

**PESQ 可微分 loss 有效（+0.14），MR-STFT 无效甚至有害（-0.04）。** 这是所有 loss 实验中最明显的一次提升，把 V3 与 V5(2.041) 的差距从 0.27 缩小到 0.13。

**为什么 PESQ 有用而 MR-STFT 没用（同为波形域 loss）：**

1. **MR-STFT 与主 gain_loss 冗余**：MR-STFT 的两项（spectral convergence + log-magnitude L1）都是**幅度谱**指标。而重建波形是 `gain × noisy谱`，实数 gain 使相位恒等于 noisy，MR-STFT 只能调幅度——正是主 `gain_loss` 已在做的事。两者抢优化同一目标，MR-STFT 的梯度反而扰乱主任务收敛。

2. **粒度冲突**：MR-STFT 在完整 161 频点上算误差，但模型只输出 22 个 band gain（插值到 161），它试图让模型匹配无法独立控制的细频点 → 无效梯度。

3. **PESQ 内置心理声学模型**：PESQ loss 不是简单幅度 MSE，而带响度压缩、掩蔽效应、非线性感知映射。它给模型的是"人耳觉得哪里重要"的加权信号，与主 gain loss **互补**（而非重复），所以能带来净增益。

**通用规律**：对实数 band-gain 结构的小模型，能带来提升的是**感知模型**（PESQ 的心理声学），而非单纯的频谱距离度量。这也解释了之前自写的低频 band 级 STFT loss 为何无提升——同属幅度冗余。

### 15.4 权衡与后续

- PESQ loss 使 **PESQ 涨、STOI/SI-SNR 略降**（STOI 0.745, SI-SNR 8.73）。符合预期：torch-pesq 直接优化感知质量，会在信噪比数值上让步。PESQ 更贴近主观 MOS，此权衡可接受。
- **决策**：放弃 MR-STFT 这条线，主推 PESQ loss。
- **待验证**：`mrstft_pesq` 叠加模式——若 ≈ 纯 pesq(1.909) 说明可容忍，若 < 1.909 说明 MR-STFT 拖后腿，则最终只用纯 PESQ loss。
- MR-STFT 若要有救，需给模型加相位/复数输出能力（如 Deep Filtering），让其有相位可优化；但那是独立大工程，暂缓。

模型文件：`model_c/v3/best_pesq_loss.pth`；结果：`evaluation/results_50/summary_20260730_145808.json`。

## 16. 蒸馏策略分析：与开源一致性 / teacher vs clean 目标矛盾性 / GTCRN gain 蒸馏可行性 (2026-07-30)

### 16.1 我们的蒸馏实现 vs 开源标准做法

| 方式 | 我们的实现 | 开源标准 | 一致性 |
|------|-----------|---------|--------|
| V5 gain 蒸馏 | student_gain ≈ teacher_gain（MSE on 22 band gains） | Hinton KD: student output ≈ teacher output | ✅ 完全一致（回归域 KD） |
| GTCRN 波形蒸馏 | student_wav ≈ teacher_wav（L1） | Waveform-level KD（TinyTTS, DistilHuBERT 等） | ✅ 完全一致 |
| FitNets hint | student 中间特征 → 线性投影 ≈ teacher 中间特征 | FitNets (Romero 2015) | ✅ 完全一致 |

结论：我们的蒸馏实现符合业界标准，没有独创或偏离之处。

### 16.2 蒸馏目标 vs Clean 目标：是否矛盾？

总 loss 结构：
```
L = gain_loss(student, clean) + w × distill_loss(student, teacher)
         ↑ hard target                    ↑ soft target
```

**直觉上的矛盾**：teacher 输出 ≠ clean（teacher 也有降噪误差），两个 loss 方向不同。

**实际不矛盾，且是蒸馏有效的核心原因**：

1. **Clean 标签对小模型太"硬"**：V3 仅 8.5K 参数 / 22 个 band gain。clean 要求每帧每 band 精确到位，但小模型表示能力有限。hard target 在模型做不到的地方产生高梯度 → 训练不稳定 / 过拟合到无法泛化的细节。

2. **Teacher 输出是"软化的"可达目标**：teacher 也不完美，它的 gain/波形隐含"哪些地方容易降、哪些降不了"的信息。Student 逼近一个"介于 noisy 和 clean 之间、但更容易达到"的目标 → 梯度更平滑、学习路径更优。

3. **Hinton 的 dark knowledge**：teacher 的"错误"本身包含结构信息——band 间相关性、噪声条件下的合理折衷。这些在 one-hot / hard target 里看不到。

**类比**：
```
                    clean 标签 (hard target)
                         ↓ (主力: 告诉方向 "去哪里")
    student ─────────────┼────────────────→ 最优解
                         ↑ (辅助: 告诉路径 "怎么去更容易")
                teacher 输出 (soft target)
```

**防止矛盾的机制**：权重比 1:0.3 (clean:teacher)，clean 标签主导方向，teacher 辅助路径。当 distill_weight 过大（如 1.0）时，teacher 缺陷会压过 clean 监督——标准做法是 0.1~0.5 之间。

### 16.3 两种蒸馏的具体互补性

| 蒸馏方式 | 作用空间 | 提供的信息 | 和 gain_loss 的关系 |
|---------|---------|-----------|-------------------|
| V5 gain | 22 band gain | 同空间的软目标：更平滑的 band gain 分布 | 同空间、方向一致但更软 |
| GTCRN 波形 | 时域波形 | 不同空间：含相位/时序/全频段感知质量 | 不同维度的约束，互补 |
| PESQ loss | 感知域 | 心理声学加权：人耳重要性 | 感知加权视角，互补 |

三者叠加时（`distill_pesq` / `distill_gtcrn_pesq`）：
- gain_loss: "band 幅度对不对"
- distill: "大模型觉得应该怎样"
- PESQ loss: "人耳觉得好不好"

→ 三个不同视角的约束，非冗余、不矛盾。

### 16.4 GTCRN 能否做 gain 空间蒸馏？

**可以。** 方法：从 GTCRN 的增强复数谱反算等效 band gain。

```
GTCRN_gain_band[b] = sqrt( E_enhanced[b] / E_noisy[b] )
```

其中 `E[b]` 是 band b 内的能量（各 bin 的 |X|² 求和）。这样就把 GTCRN 的复数 mask 输出"投影"到 22 个 band gain 空间，可以直接用现有的 V5 蒸馏框架（gain MSE）。

**优劣对比**：

| 蒸馏方式 | 优势 | 劣势 |
|---------|------|------|
| GTCRN → 波形蒸馏（当前） | 保留全频段+相位信息，teacher 的"完整能力"传给 student | 需要 -df 22 全频谱，计算量大 |
| GTCRN → gain 蒸馏（反算） | 只需普通特征，无需 -df 22，计算快，和 V5 蒸馏框架复用 | 丢失相位信息和 bin 级细节，只保留 band 级幅度包络 |

**建议**：两种都可以试。gain 蒸馏更轻量（不需要 -df 22 特征），适合快速验证 GTCRN 作为 teacher 比 V5 强多少。波形蒸馏信息更完整但计算更重。如果 gain 蒸馏就能提升，说明 GTCRN 的 band 级"暗知识"已经够用，不必用波形蒸馏。

## 17. 本轮实验关键结论汇总（Loss / 蒸馏 / 相位）(2026-07-31)

本节汇总波形域 loss、开源模型蒸馏、相位处理三条线的实验结论与讨论要点，作为后续决策依据。

### 17.1 开源模型基准（相同 50 条 DNS2020, seed=42, C 特征口径）

| 模型 | 模型路径 | 参数量 | 计算量 | PESQ | STOI | SI-SNR |
|------|---------|--------|--------|------|------|--------|
| noisy | — | — | — | 1.570 | 0.9124 | 9.21 |
| V3（我们，部署主力） | model_c/v3/ | 8.5K | ~0.82 MMAC/s | ~1.77 | — | — |
| V3 + PESQ loss | model_c/v3/best_pesq_loss.pth | 8.5K | ~0.82 | **1.909** | 0.745 | 8.73 |
| V5（验证上限） | model_c/v5/best.pth | 2.86M | ~285 | 2.041 | — | — |
| **GTCRN (dns3)** | gtcrn/checkpoints/model_trained_on_dns3.tar | 23.7K | 39.6 MMAC/s | **2.181** | 0.932 | 14.17 |
| GTCRN (vctk) | gtcrn/checkpoints/model_trained_on_vctk.tar | 23.7K | 39.6 | 1.726 | 0.868 | 9.26 |
| **DeepFilterNet3** | pip 包默认 (48kHz 原生) | ~2.31M | ~350 MMAC/s | **2.503** | 0.947 | 16.08 |

要点：
- GTCRN 训练域一致性极关键：dns3 版(2.18) vs vctk 版(1.73) 差 0.45，域不匹配泛化崩。
- DFNet3 最强(2.50)但是 ~2.31M 参数/~350 MMAC/s 的重模型，只能当 teacher，不可部署。
- 我们的 V3+PESQ(1.909) 用 GTCRN ~2% 的算力，差 0.27。

### 17.2 Loss 消融核心结论

| Loss 策略 | 结果 | 结论 |
|-----------|------|------|
| PESQ loss | PESQ +0.14（→1.909），但 SI-SNR↓、谐波糊 | ✅ 有效（感知加权），有副作用 |
| MR-STFT loss | PESQ 1.73（比 baseline 还低） | ❌ 无效/有害（幅度冗余，与主 gain loss 抢） |
| 纯 SI-SNR loss | 几乎无提升 | ❌ 幅度维度已榨干，相位动不了 |
| PESQ + SI-SNR | 不理想 | 波形域框架内难两全 |

**统一规律**：所有发生在「22 band 实数 gain 空间」内的信号（PESQ 感知加权、gain 蒸馏）**有效**；所有涉及相位/波形保真的（SI-SNR、MR-STFT、波形蒸馏）**无效**。因为输出是「实数 gain + noisy 相位」，相位维度模型根本改不了。

### 17.3 蒸馏消融核心结论

| 蒸馏方式 | 相对 baseline | 结论 |
|---------|--------------|------|
| V5 gain 蒸馏 | 提升有限 | 同构 teacher，可迁移但受 student 结构限 |
| GTCRN 波形蒸馏 | 无明显提升 | 相位残差污染梯度（student 相位=noisy，永远学不掉） |
| **GTCRN gain 蒸馏** | **优于波形蒸馏** | 反算 band gain，主动丢相位，只传 student 能吸收的信息 |

**关键洞察**：蒸馏有效性 = teacher 知识与 student 能力空间的对齐度。
- 波形蒸馏传了太多 student 接不住的信息（相位、bin 级）→ 噪声梯度拖累。
- gain 蒸馏先把知识投影到 22-band 幅度空间再蒸馏 → 传的都能吸收 → 更好。
- 推论：DFNet gain 蒸馏预期略优于 GTCRN gain，但因同样被压到 22 维，提升递减，未必值得离线预计算的工程投入。

### 17.4 蒸馏 teacher 目标 vs clean 目标是否矛盾

不矛盾。`L = gain_loss(clean) + w·distill(teacher)`，权重 1:0.3。
- clean（hard target）告诉「去哪」；teacher（soft target）告诉「怎么去更容易」。
- teacher 不完美反而好：它的软 gain 是 student 够得着的更优解，含 dark knowledge（band 相关性、噪声折衷）。
- w 过大（>1.0）时 teacher 缺陷会压过 clean，故取 0.1~0.5。

### 17.5 瓶颈定位与突破方向

**根本瓶颈 = student 结构（22 band 实数 gain + noisy 相位），不是训练信号。**
- 证据链：PESQ(gain 空间)有效 / SI-SNR(相位)无效 / gain 蒸馏 > 波形蒸馏 / 加 band 数收益递减。
- 幅度维度已接近极限，剩余差距（到 GTCRN 2.18 / DFNet 2.50）主要来自相位与 bin 级细节。

突破方向（按投入产出比）：
1. **PSM 相位敏感目标（已实现，最推荐）**：把相位差 `cos(θ_S−θ_Y)` 折进 gain 目标 `g=<Y,X>/<X,X>`，在标签层面解决相位，训练仍是 gain MSE，**推理零成本**（仍是实数 band gain）。绕开「波形域 loss 无效」陷阱。
2. **过压制惩罚（已实现）**：非对称惩罚 `relu(target−pred)²`，只罚把语音压过头，对抗 PESQ 过度降噪。
3. **Deep Filtering / 复数 mask（治本，工程量大）**：给 student 真正的相位表示能力，之前 DF 未跑通但方向对。

### 17.6 已实现的训练模式（run_server.sh ABL_MODE）

- 基础：baseline / distill(V5) / stft / distill_stft / sparse / convk5 / convk7
- 波形域 loss：mrstft / pesq / mrstft_pesq / sisnr / pesq_sisnr（需 -df 22）
- GTCRN 蒸馏：distill_gtcrn(波形) / distill_gtcrn_gain(gain空间) / distill_gtcrn_pesq
- 组合：distill_pesq
- 本轮新增：ovs（过压制）/ pesq_ovs / pesq_sisnr_ovs（含 PESQ 的需 -df 22）
- PSM：`USE_PSM=true`（特征侧开关，改 gain 目标，生成单独 _psm 特征文件，可与任意模式组合）

工程配套：run 目录名带模式 tag（如 v3_gru16_pesq_ovs_时间戳），目录内存 config.json / MODE.txt / 训练脚本快照，便于区分与复现。

### 17.7 下一步建议

1. 先验证 **PSM baseline**（USE_PSM=true + baseline）——若能同时拉起 SI-SNR 和谐波清晰度，说明相位问题在标签层面解决，找对路。
2. **PSM + pesq_ovs** 叠加——相位对齐目标 + 感知加权 + 防过压制。
3. 若 PSM 仍不够，确认必须改结构，转 Deep Filtering / 复数 mask。
4. DFNet gain 蒸馏优先级下调（预期提升递减，工程量大）。

### 17.8 环境备忘

- 服务器 GTCRN 蒸馏只需 `gtcrn/gtcrn.py` + `model_trained_on_dns3.tar`，依赖仅 torch。
- DeepFilterNet 评估：`pip install deepfilternet torchaudio`，torchaudio 新版需 `torchaudio.backend.common` shim（见 eval_deepfilternet.py）。
- PSM 改了 C 特征提取，服务器需删旧 `dump_features_16k` 重编译（run_server.sh 已加 PSM 自动重编译保护）。

### 18.6 RNNoise 新版(xiph 官方 48k) 参数量逐层计算

依据：`xiph_rnnoise/src/rnnoise_data.h` 的层维定义（一手代码）。结构 = Conv1(65→128,k2) → Conv2(128→384,k2) → GRU384×3 → Dense_out(1536→32) + VAD(1536→1)。与我们 V5 几乎相同（V5 即照此 xiph-full 复刻）。

- Conv1: (65×2)×128 + 128 = 16,768
- Conv2: (128×2)×384 + 384 = 98,688
- GRU1: 3×(384×384 + 384×384 + 384) = 885,888
- GRU2: 同 GRU1 = 885,888
- GRU3: 同 GRU1 = 885,888
- Dense_out: cat(conv2+gru1+gru2+gru3)=1536 → 32: 1536×32+32 = 49,184
- VAD_dense: 1536×1+1 = 1,537
- **合计 ≈ 2,823,841 ≈ 2.82 M**（与 V5 的 2.86M 一致，佐证 V5 = xiph-full 复刻）

计算量：GRU 为主项（3×~0.885M MAC/帧）。xiph 48kHz、帧移 480 → 100 帧/s，故 ~2.82M MAC/帧 × 100 ≈ **~280 MMAC/s ≈ 0.28 G/s**（矩阵乘主项估算，未计激活/FFT/pitch）。

> 说明：这解释了为何 xiph 新版 PESQ(2.070) 与我们 V5(2.041) 接近——两者结构、参数、算力基本相同。旧版(2018) 的 0.06M 是更小的经典结构（3 个 GRU 各 24~96），与新版差一个数量级。

## 19. Oracle 上界实验：蒸馏天花板定位 + 两个测量陷阱更正 (2026-08-03)

本节回答一个此前一直用推理代替实测的问题：**「22 band 实数 gain + noisy 相位」这套表示，到底是不是我们与开源模型差距的主因？**

方法：拿 teacher 的增强输出**反推** 22 band 增益，再应用回 noisy，得到「student 结构下能达到的最好结果」。

```
g[b] = sqrt( E_teacher[b] / E_noisy[b] )   逐 band, clamp 到 [0,1]
```

这测的不是蒸馏收益，而是**蒸馏的理论上界**：即使 student 完美复刻 teacher 的 band gain，也只能到这个分数。
- `oracle` 与 `teacher 端到端` 的差 = 表示能力损失（相位 + 带内细节），蒸馏永远拿不到。
- `oracle` 与 `V3 当前` 的差 = 蒸馏可争取空间。

脚本：`training/rnnoise_16k/dfnet_gain_oracle.py`（`--teacher-suffix` 切 teacher，`--save-gains` 导出 npy 供离线蒸馏）。
口径：50 条 DNS2020，`--max-files 50 --sample-seed 42`，与文档 §17/§18 同一批音频，可直接横向对比。

### 19.1 三 teacher 全景（50 条，PESQ-WB / STOI）

| teacher | 端到端 PESQ | →22band oracle | 表示损失 | oracle STOI | vs V3 当前(1.886) | 检测延迟 |
|---------|------------|----------------|---------|------------|------------------|---------|
| **DeepFilterNet3** | 2.502 | **2.250** (STOI 0.9412) | **0.251** | 0.9412 | **+0.365** | 0 样本 |
| xiph 官方 48k | 2.070 | 2.020 (STOI 0.8066) | 0.050 | 0.8066 | +0.134 | 160 样本 |
| V3 自身（自检） | 1.886 | 1.861 (STOI 0.7537) | 0.025 | 0.7537 | −0.025 | 160 样本 |
| — noisy 下界 | 1.570 | — | — | 0.9124 | — | — |

**V3 自反推自检是这套方法的可信度验证**：V3 本身就是 22 band gain + noisy 相位，理想情况反推再应用应当无损。实测 1.886 → 1.861，只掉 0.025 PESQ、STOI 反而略升（0.7495→0.7537）。说明 STFT / band 能量 / `interp_band_gain` / iSTFT 这条转换链本身是近无损的，前面两个 teacher 的表示损失数字可信，不是工具误差。

### 19.2 结论：表示能力**不是**主瓶颈（更正 §17.5）

§17.5 曾把「22 band 实数 gain + noisy 相位」定为**根本瓶颈**，本轮实测表明这个判断过重：

- DFNet oracle 的 **STOI 达 0.9412**，几乎追平其端到端的 0.9470；而 **V3 当前只有 0.7495**。同样的表示、同样的 22 个实数、同样的 noisy 相位，把增益值算对就能拿到 0.94 可懂度。
- DFNet oracle PESQ 2.250 已经**超过 xiph 端到端的 2.070**，也超过 GTCRN 的 2.181（§17.1）。也就是说这套表示的天花板高于我们目前想追的两个目标。
- 表示损失只有 0.251（DFNet）/ 0.050（xiph），远小于 V3 与上界的 0.365 差距。

**修正后的结论**：V3 的低分主要是**增益估计不准**，不是方法固有代价。可争取空间 0.365 PESQ / +0.19 STOI 全部落在「把 gain 估得更准」这件事上——训练信号、目标定义、模型容量都在这个范畴内，不必先改结构。

对应地，§17.5 里「Deep Filtering / 复数 mask 治本」的优先级应下调：在 gain 都还没估准的阶段，先给模型相位能力属于跳步。

### 19.3 teacher 选型：DFNet 是最优 teacher

按「可争取空间」排序，DFNet(+0.365) 是 xiph(+0.134) 的 **2.7 倍**。§17.3 曾推论「DFNet gain 蒸馏预期略优于 GTCRN gain，但提升递减、未必值得工程投入」——本轮数据不支持这个推论，DFNet 的上界优势是显著的，优先级应上调。

50 条测试集的 DFNet gain 已导出到 `evaluation/results_50/dfnet_gains/*.npy`，训练集 gain 需批量生成（这是 DFNet gain 蒸馏的主要工程成本）。

### 19.4 陷阱一：跨模型逐帧比较必须先做延迟对齐

**这是本轮最大的一个测量错误，曾产出完全反向的结论。**

不同模型的输出延迟不同（实测）：
- DFNet / GTCRN：**0 样本**
- xiph 官方 / 我们 V3：**160 样本 = 1 帧 = 10ms**（两者都有 `delayed_X` lookahead 机制，见 §六 推理引擎演进与本项目 `rnnoise_16k_pipeline.c` 的 `RNNOISE_16K_USE_DELAY`）

未对齐就计算 `E_teacher[t] / E_noisy[t]`，等于拿**两个不同时刻**的能量比当增益，结果接近噪声。修正前后对比（xiph teacher）：

| | 未对齐（错） | 对齐后（正确） |
|---|---|---|
| oracle PESQ | 1.713 | **2.020** |
| 表示损失 | 0.357 | **0.050** |
| 反推 gain 帧间 \|Δg\| | 0.141 | 0.076 |

未对齐版本算出的 oracle(1.713) 竟然**低于 teacher 端到端(2.070) 0.357**，还低于 V3 当前(1.886)，据此会得出「band 转换本身损失巨大」的错误结论。

脚本已内置 `estimate_lag()`（互相关，搜索窗 ±800 样本）自动对齐，50/50 条检出延迟完全一致（xiph/V3 全为 160，DFNet 全为 0），说明估计稳定。`--no-align` 保留用于复现旧错误做对照。

**推广规则**：本项目后续任何跨模型的逐帧/逐 band 比较（gain 蒸馏标签生成、逐帧 SNR 分析、残留噪声帧对齐）都必须先对齐延迟，否则结果无效。

> 这个错误是被用户的一句质疑抓出来的：「开源的结果本就是靠 band gain 获得的，为什么以相同方式转换反而降低，理论上不应该一样吗」——完全正确。理论上确实应该几乎无损，测出大损失就说明是测量方法有问题，而不是理论有问题。

### 19.5 陷阱二：xiph 官方是 32 band，不是 22 band（更正）

此前多处把 xiph 官方 48k 模型称为「同样 22 band」，是错的。一手代码证据：

| 证据 | 文件:行 | 值 |
|------|--------|-----|
| 输出层维度 | `xiph_rnnoise/src/rnnoise_data.h:36` | `DENSE_OUT_OUT_SIZE 32` |
| Conv1 输入维度 | `xiph_rnnoise/src/rnnoise_data.h:10` | `CONV1_IN_SIZE 65` = 2×32+1 |
| 频带边界表 | `xiph_rnnoise/src/denoise.c:63` | `eband20ms[NB_BANDS+2]` 实有 **34** 个元素 → NB_BANDS = **32** |

`xiph_rnnoise/src/denoise.h:16` 里的 `#define NB_BANDS 22` 是**我们为 16k 构建加的 shim**，不是 xiph 官方值，之前误当成了官方定义引用。

含义：xiph 官方比我们多 10 个频带、且覆盖到 20 kHz（48 kHz 采样）。所以「xiph 用同样表示却更干净」这个比较本身前提不成立——它的频率分辨率更高。不过 19.2 已说明这不是主因（DFNet 用我们的 22 band 就能到 2.250）。

### 19.6 gain 平滑损失（gsm）的前提被否定

§本轮之前基于「V3 增益抖动导致水声/musical noise」实现了 gain 平滑损失（`--gain-smooth-weight`，损失 `mean(w·(g[t]−g[t−1])²)`，默认只作用噪声帧）。本轮 oracle 数据否定了它的前提：

| gain 序列 | 帧间平均 \|Δg\| |
|-----------|----------------|
| V3 当前输出 | 0.0259 |
| **DFNet oracle（= 正确的增益）** | **0.0629** |
| xiph oracle | 0.0762 |
| V3 自反推 | 0.0663 |

**正确的增益比 V3 抖 2.4 倍**。理想增益本就该跟随信号快速变化（语音起止、瞬态），V3 的问题是「抖得**不对**」（在错误的 band/时刻变化），不是「抖得太多」。强行平滑是把它推向更远离 oracle 的方向。

实测也印证了：`best_gsm.pth`（注意只训了 9 epoch，best@epoch2，**训练严重不足，结论仅供参考**）PESQ 1.770 低于 pesq_ovs 的 1.850，而它本该优化的**谱通量方差反而从 5.65 恶化到 6.28**。

`gsm` / `pesq_gsm` / `pesq_ovs_gsm` 三个模式代码保留（`run_server.sh`），但**不再作为优化方向**。

### 19.7 修正后的优先级

| 优先级 | 方向 | 依据 |
|-------|------|------|
| ★★★ | **DFNet gain 蒸馏** | 上界 +0.365 PESQ / +0.19 STOI，是 xiph 的 2.7 倍；50 条 gain 已导出，缺训练集批量生成 |
| ★★★ | **PSM 相位敏感目标**（§17.5 已实现） | 标签层面改进 gain 目标、推理零成本，与「gain 估不准」的诊断方向一致 |
| ★★ | 过压制惩罚 ovs（已实现） | 与 PESQ 组合 |
| ★ | Deep Filtering / 复数 mask | **降级**：表示能力不是当前瓶颈，gain 都没估准时改结构属跳步 |
| ✗ | gain 平滑 gsm | **停止**：前提被 oracle 数据否定（19.6） |

### 19.8 遗留缺陷备注（未修）

`dump_features_16k.c` 中 `features[44] = .01*(pitch_index - 300)`，其中 300 是 **48 kHz 的中心值**（对齐 `xiph_rnnoise/src/denoise.c:379`）。16 kHz 下 `pitch_index` 范围 20~256，减 300 **恒为负**（−2.8 ~ −0.44），该特征退化为单调量，丢失了区分度。合理中心值约 138。

未修原因：改它需重新生成全部特征并重训，现有 checkpoint 全部作废。建议与下一次大改（如 DFNet gain 蒸馏的特征重生成）合并执行。

## 20. 外部基线对标：YongyuG/rnnoise_16k 实测 + 「容量不是瓶颈」的证据 (2026-08-06)

本节回答一个此前只能靠推测的问题：**同为 16kHz RNNoise 移植、但模型大 10 倍的开源实现，效果到底如何？我们 V3 的瓶颈是不是参数量不够？**

对标对象：[YongyuG/rnnoise_16k](https://github.com/YongyuG/rnnoise_16k)，自带训练好的 `rnn_data.c` 权重，可直接编译运行，无需复现训练。

### 20.1 结论先行

1. **容量不是 V3 的瓶颈。** YongyuG 参数量是我们的 **10.0 倍**（85,291 vs 8,567），PESQ 反而**低 0.128**。逐条比较，V3 在 **40/50 条（80%）** 上 PESQ 更好，且难/中/易三个分段全部占优 —— 不是被少数样本拉动的均值假象。这条直接否定了「加大模型即可追上 xiph」的思路。
2. **但 V3 的语音损伤明显更重。** STOI 相对 noisy 掉 **0.163**，而 YongyuG 只掉 **0.024**；SI-SNR 我们只 +0.11dB，它 +1.14dB。两边是不同取向：V3 压制激进、PESQ 高但可懂度损伤大；YongyuG 保守、少损语音但降噪量也小。
3. **发现一个我们缺失、且两个独立实现都采用的特征项**：delta-cepstrum。见 20.4。

### 20.2 评估结果（50 条 DNS2020，seed42，与历史同口径）

| 模型 | PESQ | STOI | SI-SNR | 参数量 | 相对 V3 |
|---|---|---|---|---|---|
| noisy | 1.5708 | 0.9124 | 9.21 | — | — |
| **YongyuG/rnnoise_16k** | **1.7616** | **0.8889** | **10.35** | **85,291** | −0.128 |
| 我们 V3（历史最好） | 1.8897 | 0.7495 | 9.32 | 8,567 | 基准 |
| xiph 48k 开源 | 2.0703 | — | — | 25,700 | +0.181 |
| DFNet（teacher） | 2.5034 | — | — | ~2M | +0.614 |

口径核对：本次测得 `noisy` = 1.5708 / 0.9124 / 9.2096，与历史基线 `summary_20260731_153050.json` 的 1.5699 / 0.9124 / 9.2054 吻合（PESQ 差 0.0009 来自 `wave` 与 `soundfile` 的 int16 读取路径差异，量级可忽略），因此绝对值可直接与 v3 / xiph / dfnet 比较。

### 20.4 结构与特征对比（含参数量核算依据）

YongyuG 结构：`Dense(38→24) → GRU24 → GRU48 → GRU96 → Dense(96→18)`，拓扑与 xiph 原版一致，只是把 band 从 22 降到 18。

参数量 **85,291**，从其自带 `src/rnn_data.c` 的 15 个权重数组长度**逐一累加**得到（非估算）：

| 层 | 权重 | 数量 |
|---|---|---|
| input_dense | 38×24 + bias | 912 + 24 |
| vad_gru | 24×24×3 + rec 24×24×3 + bias | 1728 + 1728 + 72 |
| noise_gru | (24+24+38)×48×3 + rec 48×48×3 + bias | 12384 + 6912 + 144 |
| denoise_gru | (24+48+38)×96×3 + rec 96×96×3 + bias | 31680 + 27648 + 288 |
| denoise_output | 96×18 + bias | 1728 + 18 |
| vad_output | 24×1 + bias | 24 + 1 |
| **合计** | | **85,291** |

关键配置差异：

| 项 | YongyuG | xiph 原版 | 我们 V3 |
|---|---|---|---|
| band 数 | 18 | 22 | 22 |
| 特征维度 | 38 = 18 + 3×6 + 2 | 42 = 22 + 3×6 + 2 | **45 = 2×22 + 1** |
| **delta-cepstrum** | **有（3×6 维）** | **有（3×6 维）** | **无** |
| 参数量 | 85,291 | 25,700 | 8,567 |
| 每帧 MAC（GRU 主导，估算） | ~8.5 万 | ~2.6 万 | ~8.6 千 |

`NB_BANDS` 需注意：`src/denoise.c` 里有两处 `#define NB_BANDS`，被 `#if SMOOTH_BANDS` 包裹，`SMOOTH_BANDS=1` 时生效的是 **18**，因此 `NB_FEATURES = 18 + 3×6 + 2 = 38`，与模型输入 38、输出 18 自洽。（我最初漏看 `#if` 分支误判为 17，已更正。）

### 20.5 对 tkd 蒸馏效果不理想的解释

结合 §19 的 oracle 结论（22band oracle 上界 2.250，DFNet teacher 2.502），本节结果补上了另一半证据：

- **不是容量问题** —— 10 倍参数的 YongyuG 反而更差。
- **是输入信息量 + 表示上限问题** —— V3 每帧只看 45 维**无差分**特征、感受野仅 3 帧（单层 `conv1(45→16)`），22 个实数增益的表示上限卡在 2.250。蒸馏只能逼近这个上限，无法突破，所以实际收益远小于按 teacher 2.502 推算的 +0.365。

据此，**优先级应从「继续调蒸馏权重/更大模型」转向「补充输入信息」**：

1. **补 delta-cepstrum 特征**（推荐先做）：xiph 与 YongyuG 两个独立实现都采用、我们唯一缺失的时序信息来源。对只有 3 帧感受野的 V3，delta 相当于免费扩展时间上下文；模型只多几百参数。属于「改输入不改 gain 目标」，按既有判据可微调而非重训。需改 `dump_features_16k.c` 重新生成特征。
2. **两层 conv（v3.1）**：已实现为独立结构轴 `MODEL_VERSION=v3.1`，感受野 3→5 帧，仅 +784 参数（9,351）。
3. 抑制过压制以换回 STOI：V3 的 ΔSTOI −0.163 有明显改善空间，可考虑调 `oversuppress` 权重。

## 21. 官方 rnnoise v0.1 实测 + 对 §20 两处错误结论的更正 (2026-08-06)

本节做两件事：补上**官方 v0.1**（此前一直缺）的实测数字，并更正 §20 里两个基于错误前提得出的结论。

### 21.1 必须从官方 git 取 v0.1，仓库里的 `src/` 不是原版

这一点是本节的前提，先说清楚。仓库根目录的 `src/` **不能**当作官方 v0.1 使用：

| 文件 | 本地 `src/` | 官方 `git tag v0.1` |
|---|---|---|
| `denoise.c` `NB_BANDS` | 18（`#if SMOOTH_BANDS` 分支内） | **22** |
| `denoise.c` `FRAME_SIZE` | `40<<2` = 160（16kHz） | `120<<2` = **480**（48kHz） |
| `PITCH_MIN/MAX/FRAME` | 20 / 256 / 320 | 60 / 768 / **960** |
| `rnn_data.c` `input_dense` | `[912]` = 38×24 | `[1008]` = **42×24** |
| `rnn_data.c` `denoise_output` | `[1728]` = 96×18 | `[2112]` = **96×22** |
| `rnn_data.c` md5 | `6b462bf4…` | `8badc897…` |
| 参数量 | 85,291 | **87,503** |

`rnn_data.c` 两者相差 **21622 行**，`denoise.c` 相差 731 行。本地那份是**18 band 重训过的 16kHz 版本**，权重数组维度都不同，拿它当「官方 0.1」会得出错误结论。

正确取法：

```bash
git clone https://github.com/xiph/rnnoise.git /tmp/rnnoise_official
cd /tmp/rnnoise_official && git checkout v0.1     # tag 有 v0.1 / v0.1.1 / v0.2
```

### 21.3 更正一：v0.1 的 STOI 是 0.9219，**高于** noisy

这条最重要。官方 v0.1 在 PESQ +0.361 的同时，**STOI 还涨了 0.0095**（0.9124→0.9219），SI-SNR +2.07dB —— 三项指标全部同向改善，没有任何以可懂度换 PESQ 的迹象。

对比我们 V3：PESQ +0.320（接近 v0.1 的 +0.361），但 **STOI 掉 0.163**、SI-SNR 只 +0.11dB。

| 模型 | ΔPESQ | ΔSTOI | ΔSI-SNR |
|---|---|---|---|
| 官方 v0.1 | +0.361 | **+0.0095** | **+2.07 dB** |
| 官方 v0.2 | +0.500 | 未测 | 未测 |
| 我们 V3 | +0.320 | **−0.163** | +0.11 dB |
| YongyuG | +0.191 | −0.024 | +1.14 dB |

**这说明 V3 的 STOI 崩塌不是「小模型的必然代价」，而是我们特有的问题。** 87K 的 v0.1 能做到三项同升，8.5K 的我们做不到三项同升可以理解，但 STOI 掉 0.163 属于另一个量级的问题 —— YongyuG 同样是 18band 重训、同样在 16k，也只掉 0.024。V3 是这批模型里唯一一个 STOI 严重倒退的。这比 PESQ 差距更值得优先排查。

### 21.4 更正二：0.1 → 0.2 只涨 0.138，delta-cepstrum 不是关键

§20.5 我建议「优先补 delta-cepstrum」，理由是「xiph 与 YongyuG 两个独立实现都采用、我们唯一缺失」。这个推理有两处错：

1. **YongyuG 不是独立印证。** 它是 0.1 血统的 16k 移植（18 band / 38 特征），与 0.1 同源，等于只有一个来源，不构成「两个独立实现都选择」的证据。
2. **xiph 最新版已经删掉了它。** 0.2 的 `NB_FEATURES = 2*NB_BANDS+1` = 45，全仓无 `NB_DELTA_CEPS`；我们 `denoise_16k.h:23` 与之逐字相同。所以我们不是「缺失」，而是**与最新版一致**。

各版本特征对照：

| 版本 | 特征公式 | 维度 | delta-cepstrum | 参数量 | PESQ |
|---|---|---|---|---|---|
| 官方 v0.1 | `NB_BANDS+3*NB_DELTA_CEPS+2` | 22+20 = 42 | **有** | 87,503 | 1.9305 |
| 官方 v0.2 | `2*NB_BANDS+1` | 44+1 = 45 | **无** | 25,700 | 2.0703 |
| 我们 V3 | `2*NB_BANDS+1` | 44+1 = 45 | **无** | 8,567 | 1.8897 |

0.1 → 0.2 的收益是 **+0.138 PESQ，同时参数量降到 29%**（87,503 → 25,700）。xiph 在删掉 delta 的同时把结构从纯 GRU 改成带 conv 前端 —— 用 conv 的时间感受野替代手工差分特征，效果更好且更省。

**结论：撤回「补 delta-cepstrum」的建议。** 它是 0.1 的设计，官方已在 0.2 主动移除并取得更好结果，补它等于逆着上游演进方向回退。

### 21.5 修正后的优先级

按实测证据重排：

1. **查 V3 的 STOI 为何掉 0.163**（最高优先）。这是 V3 独有的异常：v0.1 是 +0.0095、YongyuG 是 −0.024，只有我们是 −0.163。可能来源：过压制（`oversuppress` 权重不足）、gain floor 策略、或 22band 实数增益在低 SNR 段把语音一起压掉。这项不解决，PESQ 再优化也是拿可懂度换分。
2. **v3.1 两层 conv**（已就绪）。方向与 0.2 一致 —— 用 conv 感受野替代手工时序特征，本质是把 0.2 的做法补回来，感受野 3→5 帧，仅 +784 参数。
3. **核对我们 45 维特征与 `xiph_rnnoise/src/denoise.c` 是否逐项一致**。同样 45 维、同样 22 band，0.2 是 2.0703 而我们 1.8897；若特征实现有偏差，那才是真正的差距来源。
4. ~~补 delta-cepstrum~~ —— 已撤回，见 21.4。

## 22. 新增 STOI loss + 增益分布诊断：定位 V3 的 STOI 崩塌机制 (2026-08-06)

§21 发现 V3 的 STOI 相对 noisy 掉 0.163（官方 v0.1 是 **+0.0095**、YongyuG 是 −0.024，V3 是唯一严重倒退的）。本节把这个现象**拆解到机制层面**，再据此决定加什么 loss。

### 22.1 先做诊断，而不是直接加 loss

「STOI 低」有两种成因，解法完全相反，只看 STOI 数值无法区分：

| 成因 | STOI loss 是否有效 | 正确解法 |
|---|---|---|
| A 均匀过压制（所有带同比例压小） | **无效** | `--oversuppress-weight` |
| B 不一致压制（某些带/帧被压没、逐帧抖动） | **对症** | STOI loss |

A 无效的原因是 STOI 算法**第一步就做逐段能量归一化**（`norm = ‖Xr‖/‖Xh‖`），线性增益被直接除掉。我实测确认了这一点：把信号整体压到 0.4 / 0.1 倍，我的 `STOILoss` 输出 0.0000，**pystoi 对同样输入也给 1.0000** —— 这不是实现 bug，是 STOI 的定义使然。

所以先量增益分布（`diag_gain_distribution.py`，20 条、只统计语音帧、逐 band 对比 V3 与官方 v0.1 相对 clean 的 dB 增益）：

| 指标 | 我们 V3 | 官方 v0.1 | 判读 |
|---|---|---|---|
| 语音帧平均增益 | **−2.53 dB** | +0.09 dB | A 存在，需 ovs |
| 带间不一致（std） | 1.35 dB | 1.13 dB | 差别不大，不是「某带被压没」 |
| **帧间波动（std）** | **7.95 dB** | **5.03 dB** | **B 是主因（高 58%）**，STOI loss 对症 |

逐 band 看，V3 在 100Hz–4400Hz 几乎每个 band 都压 −1.1 ~ −5.7dB，而 v0.1 基本在 ±1dB 内浮动（只有最高带 7100Hz 压 −3.8dB，那是合理的低通）。

**结论：两种损伤都存在，但主因是帧间抖动。** ovs 治 A、STOI 治 B，互补不重叠，应同时开。

### 22.2 实现：可微 STOI loss

`waveform_losses.py` 新增 `STOILoss`，严格按 Taal et al. TASLP 2011（即 pystoi 实现的算法）：

1. 重采样到 10kHz（STOI 标准，分带边界依赖它，不能省）
2. 15 个 1/3 倍频程带（中心频率 `150 * 2^(k/3)`，边界 `f_c / 2^(±1/6)`）
3. 切成 30 帧（384ms）重叠短时段
4. 每段能量归一化 + **削波**（`y' = min(y_norm, x*(1+10^(β/20))), β=−15dB`）—— 这一步是 STOI 能反映过压制的关键
5. 逐段逐带算相关系数，全部取平均；`loss = 1 − STOI`

与 pystoi 的有意差异（都为可微/可批处理）：不做 VAD 静音段移除（训练时长度不定无法批处理）、用 `torch.stft` 而非逐帧 numpy、重采样用线性插值（1/3 倍频程带对重采样滤波器细节不敏感）。**因此本类输出不能与评估用的 pystoi 数值直接比较，验收仍以 `evaluate_models.py` 的 pystoi 为准。**

自测结果（接进训练前的必要验证）：

| 检查项 | 结果 |
|---|---|
| 恒等 `loss(y,y)` | 5e−6（≈0）✓ |
| 噪声单调性 SNR 20→−5dB | 0.025 → 0.037 → 0.047 → 0.069 → 0.098 单调 ✓ |
| 与 pystoi 排序一致性 | 相关系数 **−0.985**（强负相关）✓ |
| 梯度非零 | mean 1.3e−4、max 4.1e−3 ✓ |
| 整体线性缩放敏感性 | **不敏感**（已知局限，见 22.1）⚠️ |

### 22.3 训练接线

`train_rnnoise_16k.py` 新增 `--stoi-loss-weight`（默认 0=关），共 12 处接线：`use_wav` 判定、run 目录 tag、开关打印、`_active` 摘要、config.json、MODE.txt、csv 表头/行、running 累加、进度条、loss 计算。

`run_server.sh` 新增三个模式：

| ABL_MODE | 组成 | 用途 |
|---|---|---|
| `stoi` | STOI | 单独消融，看 STOI loss 本身的效果 |
| `pesq_stoi` | PESQ + STOI | 直接对应两个评估指标 |
| **`pesq_stoi_ovs`** | PESQ + STOI + ovs | **按 22.1 诊断推荐**：三者分工不重叠 |

权重 `ABL_STOI_WEIGHT=0.3`（loss 量级自测 0.03~0.10，与 gain_loss 同量级）。

三个模式都已加入 `is_wav_mode()` —— 漏加会让特征退回 `-df 12`，波形重建直接崩（这个坑 §1 踩过一次）。dry-run 验证三者都正确打印「强制 -df 22 全频谱特征」，且 `stoi_typo` 这类拼写错误仍被拦。


### 22.5 待确认
